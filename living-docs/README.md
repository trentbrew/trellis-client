# Living Docs

This directory holds **auto-generated documentation** that the TQL Living Docs system maintains alongside the codebase.

> Do not hand-edit the auto sections. They are regenerated from the TQL kernel on every commit and your changes will be overwritten.

## How it works

```
git commit
   ↓
.husky/post-commit
   ↓
hooks/tql-docs-sync.ts
   ↓
reads:  .tql/docs.trellis.jsonld   (DocModule definitions)
        + the TQL kernel state
   ↓
writes: living-docs/<MODULE>.md     (rendered output)
   ↓
git commit --amend                  (folds the regenerated docs into the same commit)
```

Each output file has a footer that records when it was last generated:

```
*Auto-generated by [TQL Living Docs](../.tql/docs.trellis.jsonld) at <ISO-8601 timestamp>*
```

## What's in here

| File              | DocModule                                | Source                      |
|-------------------|------------------------------------------|-----------------------------|
| `CHANGELOG.md`    | Commit log + code-change tracker         | Git history + TQL events    |
| `CONVENTIONS.md`  | Code conventions registry                | TQL `Convention` entities   |
| `DATA_LAYER.md`   | Data flow + adapter inventory            | Code scan + TQL kernel      |
| `DECISIONS.md`    | Architectural Decision Records           | TQL `Decision` entities     |
| `ENTITY_SYSTEM.md`| Entity ontology + class/type matrix      | `tql-ontologies.ts`         |
| `ROADMAP.md`      | Milestones + features in flight          | TQL `Milestone` entities    |
| `SPEC.md`         | Product spec snapshots                   | TQL `Spec` entities         |
| `THEME.md`        | Theme presets + token registry           | `theme-presets.ts`          |
| `TQL_HOOKS.md`    | Hook lifecycle + event surface           | `hooks/*.ts` scan           |

A file shows `*No X defined yet.*` when no source entities exist yet — it's not broken, just empty.

## Manual sections (hybrid mode)

Some files support hybrid auto + manual sections via marker comments:

```markdown
## Auto-generated section
... regenerated on every commit ...

<!-- manual:start -->
## Manual notes
You can write here. tql-docs-sync preserves this block.
<!-- manual:end -->

## Another auto section
... regenerated on every commit ...
```

## Regenerating manually

```bash
# Regenerate everything regardless of diff
pnpm hq:docs        # ← bun run hooks/tql-docs.ts --all

# Regenerate diff-aware (matches what runs on commit)
pnpm hq:docs-sync   # ← bun run hooks/tql-docs-sync.ts --all --no-amend
```

## Why this exists

Trellis is a knowledge-graph platform. Treating documentation as a TQL projection means:

- Decisions, conventions, and milestones live in the graph as queryable entities.
- Markdown is a render target, not the source.
- Agents can introspect the same data the docs are built from via MCP tools.

See `AGENTS.md` and `docs/architecture/` for the underlying architecture.
